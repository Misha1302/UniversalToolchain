UniversalToolchain: Руководство для разработчиков
=================================================

Архитектурные принципы
----------------------

### 1\. Модульная архитектура (не микросервисная)

*   **Факт**: Реализация модульная, но монолитная в одном процессе
    
*   **Документация**: Обновить раздел "Архитектура", убрать упоминания о микросервисах и REST API
    
*   **Код**: Все модули реализуют `ICoreModule` и выполняются в порядке их передачи в `BasicCoreImpl`
    

### 2\. Структура байткода

*   **Текущая реализация**: `(Tags, Ops[приоритеты])` через `LevelCollection<float, IDynamicMethodConvertable>`
    
*   **Преимущество**: Решает проблему O(N²) связности между модулями
    
*   **Пример взаимодействия**:
    
    csharp
    
    Copy
    
    Download
    
    // Модуль А добавляет проверку
    instruction.Ops\[\-10\].Add(new CheckBoundsOp());
    
    // Модуль B добавляет логирование (не зная о модуле A)
    instruction.Ops\[10\].Add(new LogOp());
    

### 3\. Порядок выполнения модулей

*   **Правило**: Модули выполняются в порядке передачи
    
*   **Зависимости**: Разработчик должен передавать модули в правильном порядке
    
*   **Проверка**: Нет автоматической проверки зависимостей - это ответственность разработчика

### 2\. Конфликты между модулями

*   **Проблема**: Два модуля добавляют одинаковые лексемы/синтаксис
    
*   **Решение**: Будет выброшено исключение на этапе инициализации
    
*   **Рекомендация**: Используйте уникальные имена для своих конструкций
    

### 3\. Работа с типами

*   **Система типов**: Основана на интерфейсах (`IGettable<T>`, `ISettable<T>`, `IAddable<T>` и др.)
    
*   **Проверка типов**: Происходит во время генерации CIL кода
    
*   **Рекомендация**: Следуйте контрактам интерфейсов, проверяйте совместимость типов

Производительность и оптимизации
--------------------------------

### 1\. Текущая стратегия

*   **Интерпретатор**: Не оптимизирован, предназначен для отладки
    
*   **CIL компилятор**: Основной бекенд, должен генерировать оптимальный код
    
*   **DynamicMethod**: Всегда остаются в памяти, нет пулинга
    

### 2\. Рекомендации по оптимизации

*   Фокусироваться на оптимизации CIL компилятора
    
*   Не тратить время на оптимизацию интерпретатора
    
*   Добавлять оптимизации через отдельные модули
    

Интероперабельность с C#
------------------------

### 1\. Текущие возможности

*   Вызов статических публичных методов
    
*   Поиск методов через `MethodsFinder.GetMethod`
    
*   Поддержка generic методов через сложную логику в `IlCodeGenerator`
    

### 2\. Ограничения

*   Нет поддержки перегруженных методов (выбирается первый найденный)
    
*   Нет поддержки extension-методов
    
*   Generic параметры выводятся автоматически, могут быть ошибки
    

### 3\. Рекомендации

*   Используйте явные имена методов
    
*   Проверяйте совместимость типов
    
*   Избегайте сложных generic конструкций
    

Отладка и тестирование
----------------------

### 1\. Текущее состояние

*   **Тесты**: Существуют, но не предоставлены в анализе
    
*   **Отладка**: Будет реализована через отдельный модуль
    
*   **Профилирование**: Нет встроенных инструментов
    

### 2\. Рекомендации

*   Используйте `ExecutorDebugLoggerImpl` для логирования этапов компиляции
    
*   Пишите unit-тесты для своих модулей
    
*   Для отладки используйте стандартные средства .NET
    

Критические участки кода
------------------------

### 1\. `ScopesCreator.FormScopes`

*   **Проблема**: Модификация коллекции во время итерации
    
*   **Статус**: Требует проверки на корректность
    
*   **Действие**: Написать тесты для edge cases
    

### 2\. `BasicLexerImpl.Lexemize`

*   **Проблема**: Потенциальные проблемы с производительностью
    
*   **Решение**: Убедиться, что регулярные выражения кэшируются
    
*   **Действие**: Добавить бенчмарк для лексера
    

### 3\. `IlCodeGenerator.LdArgsAndCall`

*   **Проблема**: Сложная логика приведения типов
    
*   **Статус**: Требует дополнительного тестирования
    
*   **Действие**: Написать тесты для всех возможных сценариев

*   Помните о порядке выполнения операций по приоритетам

Известные проблемы и ограничения
--------------------------------

### 1\. Архитектурные

*   Нет механизма разрешения зависимостей между модулями
    
*   Нет формальной спецификации AVM
    
*   Отсутствует система плагинов для IDE
    

### 2\. Технические

*   Утечки памяти из-за `DynamicMethod`
    
*   Сложная логика приведения типов
    
*   Ограниченная интероперабельность с C#
    

### 3\. Документационные

*   Несоответствие между документацией и реализацией
    
*   Недостаточно примеров использования
    
*   Отсутствие API документации
