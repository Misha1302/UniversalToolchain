\section{Implementation}
We implemented the model in System W, an extensible .NET compiler framework. Pipeline observers receive bytecode, AIR, and optimized AIR artifacts from the actual compiler path. The effect verifier evaluates contracts against selected module order and emits reverification requests. The scheduler resolves requests to production \texttt{BytecodeVerifier} and \texttt{AirVerifier} routes. Telemetry records invalidations, obligations, per-rule invocations, first detection boundary, diagnostics, elapsed verifier time, allocations, and process identity.

The policy switch is execution-scoped and does not expand the public facade. The production integration rejects unknown policies, unknown routes, canonical-owner conflicts, and empty scopes for requested checks. A separate lazy-demand scheduler consumes the same invalidation records but selects only routes named by an explicit consumer demand. It is intentionally not folded into the frozen P0--P3 enum or historical result schema.

\paragraph{Mixed numeric promotion repair.}
The source-to-result corpus exposed a pre-existing failure when a floating-point parameter was combined with an integral literal. The native arithmetic visitor previously required identical CLR operand types. We replaced the assertion with deterministic binary numeric promotion before selecting the managed arithmetic method. The original program remains unchanged and now serves as a valid regression control rather than being removed from the corpus.

\paragraph{TensorRules.}
To test whether the mechanism is tied to System W internals, we implemented a second package solely through public language-authoring SDK projects. TensorRules has its own parser, typed \texttt{TensorPlan}, shape/layout/backend facts, optimizer, and interpreter. Policy and fault selection travel through a public execution request; no System W project is referenced. TensorRules is model-authored and is not presented as an independently authored language.
