\section{Methodology}
\subsection{Research questions}
\begin{description}
 \item[RQ1:] Which declared semantic faults are missed by generic structural verification?
 \item[RQ2:] What enforcement does boundary-indexed obligation discharge add beyond passive invalidation and demand-driven recomputation?
 \item[RQ3:] How do selective P2 and always P3 compare in detection, localization, and verifier work on the evaluated cases?
 \item[RQ4:] Do the policy distinctions persist in a public-SDK language, and what independent-validity evidence remains unavailable?
\end{description}

\subsection{Versioning and accounting}
Historical raw evidence, manifests, and P0--P3 denominators remain immutable. New policies and cases use new schema/protocol versions. Each aggregate separates the historical study set from demand-specific additions. Raw JSONL is opened and flushed before validation; failed assertions therefore retain the observations that caused them. Repetitions check process isolation and determinism, but are not counted as independent semantic cases.

The active protocol uses two catalogues.  The immutable v3 catalogue retains the original P0--P3 rows and checksum.  A separate v4 demand catalogue contains only the matched queried/unqueried additions.  CI validates both checksums and rejects a v4 row in a historical denominator.  This repair was necessary after an initial hardening revision accidentally mixed the two catalogues; no result from that mixed revision is used here.

\subsection{Units, outcomes, and oracle independence}
The semantic case, not a process repetition, is the primary unit of analysis. For each case we compare policies on four predeclared outcomes: accepted versus rejected classification, diagnostic family, first detection boundary, and source-to-result behavior. Repeated fresh processes are a determinism check; a case that succeeds twice is still one semantic observation. Policy comparisons therefore use paired discordance counts and absolute differences rather than treating repeated executions as independent samples. Controls remain in every denominator, and a policy that rejects a control is reported as a false positive rather than silently removing the case.

Oracles are fixed before reading the candidate policy result. Boundary and ablation oracles come from the declared fact transition, canonical owner, and first eligible boundary. Source-to-result controls use the language result specified by the program; injected faults use the expected diagnostic family and boundary encoded by the mutation contract. The matched demand pair shares the same artifact mutation and verifier route, differing only in whether a downstream query is issued. Historical oracles are derived from the original issue and fixing regression, while any future external corpus must be frozen and checksummed before policy execution. P3 is a comparison policy, not the oracle: P2/P3 agreement can support parity on the evaluated cases but cannot establish verifier soundness.

\subsection{Boundary corpus}
The historical primary set contains 32 operator shapes, the post-freeze challenge set contains 10, and the historical valid-control set contains 100 controls per policy. Protocol v4 adds P1D, two matched demand cases, and 20 new controls per policy without changing historical denominators. The demand cases differ only in whether a downstream query is issued. The oracle requires P1D to reject the queried case and miss the unqueried case; P2/P3 must reject both at the first eligible boundary.

\subsection{System W source-to-result corpus}
Protocol v3 retains the historical 30 programs as a named study set and adds two matched demand programs. The repaired P07 source and expected value are unchanged. The resulting 32 programs contain 25 valid controls and seven targeted faults. Every case/policy pair runs twice in a fresh process: $32\times5\times2=320$ raw records. The oracle records classification, result, diagnostic family, and first detection boundary. CIL faults can compile to wrong results under non-enforcing policies; interpreter faults can reach a later runtime failure.

\subsection{Language T corpus}
Schema v2 retains 12 historical cases and adds two matched demand cases. The 14 cases comprise two valid programs, two intrinsically invalid programs rejected before post-verification mutation, and ten post-verification faults. Five policies produce 70 observations. P2/P3 classification parity and the P1D queried/unqueried split are hard validation gates.

\subsection{Mechanism ablations}
Eight minimal counterexamples each have a matched valid control. For producer identity, source identity, selected order, canonical ownership, conflict rejection, unresolved routing, backend capability, and repeated occurrence, the full mechanism must emit the predeclared diagnostic and the corresponding one-mechanism ablation must lose that detection without rejecting the control. These are necessity witnesses for the constructed cases, not estimates of real-world prevalence.

\subsection{External and historical validity}
The external-author packet specifies public information, allowed SDK surface, fault/control schema, freeze/checksum procedure, safe import validation, and complete accounting. No human-authored frozen archive was available, so that result is \texttt{BLOCKED\_EXTERNAL}.

For historical evidence, we froze criteria before searching repository issues, fix commits, regression tests, and checked-in review notes through 29 July 2026.  The resulting accounting table contains 24 records: three issue-defined semantic defects are included, eleven records are excluded by the frozen criteria, and ten potentially relevant aggregate fixes are retained as blocked because the available export lacks an independently frozen one-root reproducer or oracle.  The three included issues each contain a source program, expected result or diagnostic family, and pre-study 3/3 fresh-process confirmation.  We exported the selected pre-fix source and attempted a new offline replay.  Its old dependency graph built through most projects, but the bounded host terminated Roslyn before the campaign began.  We therefore classify the new replay as \texttt{BLOCKED\_RESOURCE}; we do not count the original issue evidence as a new policy experiment and report no historical P2 detection rate.

\subsection{Cost evidence}
We report verifier invocations and boundary-kernel timing only as qualitative work evidence. Hosted CI is a reproducibility provider, not a decision-grade performance host. Whole-compilation timing remains blocked until a pinned-machine protocol records affinity, governor, load, runtime/toolchain, at least 30 independent process replicates per cell, raw distributions, and paired bootstrap intervals.
