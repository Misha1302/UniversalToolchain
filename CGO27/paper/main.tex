\title{Valid IR, Invalid Compiler: Contract-Guided Reverification for Extensible Pipelines}
\author{Anonymous Author(s)}

\begin{abstract}
An extensible compiler may produce structurally valid intermediate representation while violating a semantic assumption of the selected language, optimization, or backend configuration. Existing pass managers invalidate cached analyses, and translation validators check particular transformations, but neither mechanism by itself answers which semantic checks an extension must re-run after it changes a selected pipeline. We present contract-guided reverification: compiler components declare owned facts, effects, invalidations, and verifier routes; a fail-closed scheduler then supports structural-only, invalidation-only, selective, and always-verify policies over the same boundaries.

We implement the mechanism in an extensible .NET compiler and evaluate it in two language packages. On a frozen boundary corpus, structural checks detect 12/32 primary operator shapes, invalidation-only detects 28/32, and selective and always verification both detect 32/32; the corresponding challenge counts are 1/10, 10/10, 10/10, and 10/10, with no false positives in 100 valid controls per policy. A source-to-result System W study contains 30 programs and 240 fresh-process records. Five targeted optimizer faults yield wrong results or later runtime failures under structural/invalidation policies, while selective and always verification reject all five at the optimized-IR boundary. A public-SDK TensorRules package contributes eight different semantic faults and 48 observations, again with selective/always classification parity. Ablations show that typed contracts and obligation discharge account for distinct detection gains. Selective verification executes fewer clean-boundary verifier calls than always verification, but the observed 14.3\% boundary-call reduction is below our predeclared efficiency threshold; we therefore make no whole-compilation speedup claim. External-corpus and pinned-machine performance claims remain explicit blockers.
\end{abstract}
