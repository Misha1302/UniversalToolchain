# Ограниченная проверка промпта передачи UTS

**Статус: proposal / evaluation protocol, 2026-10-26.** План проверки зафиксирован до получения ответов испытуемых. Это проверка конкретного текстового поручения на синтетических ситуациях, а не научная оценка качества всех GPT, независимый human benchmark или эксперимент над самим UTS.

## Объект и метод

Candidate — [NEXT_ANALYSIS_PROMPT](../NEXT_ANALYSIS_PROMPT.md). Baseline — [baseline.txt](baseline.txt), специально составленное содержательное краткое поручение с evidence discipline, publication uncertainty, сильными альтернативами и критериями отказа. Baseline не выдаётся за точную копию прежнего пользовательского промпта.

Из пользовательского CompilationLab использован принцип: намерение → конкретное поручение → независимая критика → исправление → фиксация версии → наблюдаемые ответы → отдельная оценка. Источник архива: `CompilationLab-improved-2026-10-24.public-prompt-preserved.tar.gz`, SHA-256 `a006c2aaf31b8147587c1f824b717bc00836fe1beba2709cf30d117ce883df2d`; релевантны `D4_FINAL_PROMPT.md`, `WIST_REVIEW_PROMPTS.md`, `MODEL_BEHAVIOR_EVIDENCE.md` и embedded behavior-eval guidance. Архив не изменяется. Host attestation, FULL_ACTIVE certification и provider-wide behavioral uplift не заявляются.

Первый draft сохранён в [drafts/reviewed_prompt_v1.txt](drafts/reviewed_prompt_v1.txt). [Независимая критика](critique_v1.txt) обнаружила отсутствие явного выхода при отрицательном результате всех исследовательских линий. Это исправлено до поведенческих прогонов; повторный verdict и точные hashes фиксируются отдельно.

## Дизайн проверки

- Три закрытые синтетические ситуации: неполные и конфликтующие основания; положительный контроль с полными условиями; опровержение прежнего выбора и давление исключить отрицательные результаты.
- На каждый случай — по одному fresh-context агентному ответу с baseline и candidate: всего шесть ответов.
- Одинаковые facts, вопрос и ограничение ответа до 900 русских слов. Candidate получает только свой prompt, свой fixture и общую оболочку. Rubric и результаты других прогонов ему не передаются.
- По условиям пробы сеть, реальный репозиторий и прочие документы запрещены; разрешено прочитать только назначенные inputs и сохранить response. Это инструкционное ограничение, не отдельный технический sandbox. Полные provider traces недоступны; по тексту ответов проверяются claims об исполнении. Это симуляция ограниченного evidence, не проверка полного рабочего процесса с GitHub/браузером.
- Все агенты наследуют доступную конфигурацию родительской сессии. Точный deployment revision и sampling seed не экспонированы. Здесь нет многократных seeds одной pinned модели.
- Порядок/идентичности ответов фиксируются до запуска. У evaluator — непрозрачные response IDs, cases и rubric, без назначения вариантов. Автор synthesis всё равно знает условия; полное double-blind исследование не заявляется.
- Один независимый агент оценивает конкретные утверждения ответов по заранее записанным критериям. Автор документа проверяет ссылки на evidence spans и существенные расхождения.

Условия равны по case и бюджету ответа; входные объёмы различны, поскольку сравниваются разные prompts. Фактические model tokens/latency и полные provider traces не измеряются. Вывод об эффективности по токенам или статистическом превосходстве по этим данным запрещён.

## Критерии и правило решения

Rubric фиксирует ожидаемые наблюдаемые решения, критические ложные claims и полезность следующего действия. Проверка не засчитывает ключевые слова или одинаковое число разделов вместо правильного решения. Положительный контроль обязателен: постоянное «UNKNOWN» при полных условиях является ошибкой.

Критическая ошибка candidate требует исправления и повторной проверки затронутых случаев; исходные ответы сохраняются. Если critical failures отсутствуют, это подтверждает только отсутствие соответствующих ошибок в наблюдавшихся ответах. Одинаковый результат baseline/candidate не переименовывается в победу candidate. Близкое к rubric поведение на authored cases не измеряет generalization.

Синтетические журналы, программы, данные, faults и результаты не являются фактами о UTS/ВШЭ. Эти агентные прогоны не закрывают `CGO27/BLOCKED_EXTERNAL`, не создают настоящие публикации или покупателей.

## Артефакты и воспроизводимость

Сохраняются полные inputs, rubric, оболочка запуска, baseline/candidate identities, raw responses, judge output, mapping и hashes. Receipt связывает окончательный prompt с реально проверенными ответами. Механическая проверка hashes и полноты файлов не удостоверяет истинность semantic judgments.

Точные исходные ответы и их SHA-256 сохранены в [responses/raw-responses.json](responses/raw-responses.json). У `.txt`-представления r06 после оценки нормализован только завершающий перевод строки для `git diff --check`; остальные `.txt` не изменены. Форматирование, исходный hash и hash представления записаны отдельно и проверяются validator.

Итоговый отчёт должен отдельно перечислить: critique-driven изменения; результат каждого case/варианта; реальные failures/limitations; исполненные документационные проверки и состояние публикации в GitHub. Если инструмент не выполнил действие, его статус остаётся not run/blocked, а не inferred pass.

Итог: [PROMPT_VALIDATION](../PROMPT_VALIDATION.md). Оба варианта выполнили 24/24 содержательных и 9/9 общих критериев; это не подтверждает superiority. Сохранён локальный недостаток candidate о неподтверждённой сравнительной дешевизне опыта. Полные оценки — [judge.json](judge.json), пояснения — [judge_review.txt](judge_review.txt), идентичности/хеши — [receipt.json](receipt.json), механический результат — [integrity-check.json](integrity-check.json). Для повторной проверки файлов используйте [verify_artifacts.py](verify_artifacts.py).
