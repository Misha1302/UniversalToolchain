# Scientific prior-art delta and actual competitor controls (2026-10-12)

**Status: targeted independent comparison; not a systematic literature review and not a novelty claim.** Each link below is a public primary publication/official implementation document checked during this review. Dates are the cited work's dates, not the date when a webpage was crawled. The repository's older [comparative strategy](STRATEGY_PRIOR_ART.md) remains the canonical historical comparison; this document records what directly constrains the next decision.

## Work-by-work comparison

| Prior art and evidence | Implemented / demonstrated mechanism | Impact on Ideal UT; adaptation boundary |
| --- | --- | --- |
| **Kaminski, Kramer, Carlson, Van Wyk (2017), _Reliable and Automatic Composition of Language Extensions to C: the ableC Extensible Language Framework_** ([MELT/ableC official](https://melt.cs.umn.edu/ableC/), [paper DOI](https://doi.org/10.1145/3138224)) | Composable independently authored extensions to C11 via Silver plus modular scanner/AG well-definedness checks. Published examples include algebraic data types, SQLite, Cilk, regex and closure syntax. | Most direct counterexample to “UT invented independent language extensions.” UT's potential distinct question is selected-world **cross-representation evidence and execution routes**, not syntax composition alone. Use independently certified ableC extension authoring as a strong competitor, though its C host and runtime differ from UT. |
| **Van Wyk, Bodin, Gao, Krishnan (2010), _Silver: An Extensible Attribute Grammar System_** ([paper](https://doi.org/10.1016/j.scico.2009.07.004)) | Attribute grammars, forwarding and extension-defined static analyses; practical compiler specification language. | A narrow attribute-based semantic flow may avoid a new global fact database. Strong baseline for AST-local facts and inherited/synthesized semantics. Does not by itself establish UT's exact selected executable hashes and cross-IR revocation. |
| **MLIR _Interfaces_ and _Dialect Conversion_** ([interfaces](https://mlir.llvm.org/docs/Interfaces/), [conversion](https://mlir.llvm.org/docs/DialectConversion/)) | Operation/dialect interfaces decouple consumers from concrete operations; partial/full/analysis conversion with legality checks, rewrite patterns and optional type conversion. | Strongest mature **within-IR-family** baseline for “new provider helps old pass.” UT should not build another op-interface hierarchy without evaluating MLIR patterns. For structurally unrelated artifacts, a transport witness may be harder than converting/reanalysing. |
| **MLIR _IRDL_ and _PDLL_** ([IRDL](https://mlir.llvm.org/docs/Dialects/IRDL/), [PDLL](https://mlir.llvm.org/docs/PDLL/)) | Declarative dialect and rewrite description, constraint validation and generated compiler plumbing; IRDL distinguishes constraints that need native C++ code. | “All operations are data + typed handler” has substantial prior art. Use as design control for declarative authoring, not evidence that any declarative rewrite is sound. |
| **LLVM _Using the New Pass Manager_** ([manual](https://llvm.org/docs/NewPassManager.html)) | Cached on-demand analyses and explicit `PreservedAnalyses` invalidation, with notable nested-analysis/concurrency limitations. | Correctness-preserving cache invalidation is not new. Begin with LLVM-style conservative invalidation; extend to executable digest and cross-artifact proof only when experiments require them. |
| **Salsa incremental framework** ([reference](https://docs.rs/salsa/latest/salsa/)) | Memoized tracked queries record dependencies and invalidate incrementally. | Strong alternative to building a custom persistent fact store for IDE/document indexing. A compiler-only single-shot semantic check may need neither Salsa nor a cache. |
| **Lopes, Lee, Hur, Liu, Regehr (2021), _Alive2: Bounded Translation Validation for LLVM_** ([PLDI paper](https://web.ist.utl.pt/nuno.lopes/pubs/alive2-pldi21.pdf)) | Bounded translation validation of LLVM transformations by SMT-based reasoning under modeled LLVM semantics. | Distinguish checked optimization equivalence from an asserted property. A hypothetical UT independent checker must state its language/IR domain, supported operations, solver bounds and proof gaps. Alive2 does not validate arbitrary UT AST/CIL/Python routes. |
| **Leroy (2009), _Formal Verification of a Realistic Compiler_, and CompCert documentation (version 3.18, 2026)** ([paper](https://xavierleroy.org/publi/compcert-CACM.pdf), [current proof sources](https://compcert.org/doc/)) | Machine-checked semantic preservation of a *specified* source language through particular transformations to assembly. | A genuine preservation theorem quantifies over an explicit semantics; “same semantics on every platform” is meaningless without an observation model. UT should use independent translation oracles for bounded components rather than promise universal equivalence. |
| **Willsey, Nandi, Wang, Flatt, Tatlock, Panchekha (2021), _egg: Fast and Extensible Equality Saturation_** ([POPL paper](https://doi.org/10.1145/3434304)) | E-graph rebuilding and e-class analyses for equality saturation; conditional rules still require sound premises. | Keep e-graphs as an optional *optimization engine*, not global semantic truth. More rewriting alternatives do not resolve trust or provider identity; saturation may be costly. |
| **Soufflé provenance** ([official documentation](https://souffle-lang.github.io/provenance)) | Lazy explanation trees with rule identity for derived Datalog tuples. | Proof DAG explanation is existing engineering, not a UT novelty claim. Provenance can explain a deduction without establishing its source premises as true. Only consider a bounded rules kernel after two independent true-transitive workloads. |
| **Findler, Klein, Fetscher, Felleisen, _PLT Redex_** ([manual](https://docs.racket-lang.org/redex/index.html)); **Racket macros** ([reference](https://docs.racket-lang.org/reference/Macros.html)) | Executable reduction semantics, tests, syntax objects with binding/hygiene and macros that extend host compilation. | Strong tools for *specifying and falsifying* a C-like semantics before porting it to UT. Racket syntax extensions are not automatically multi-backend optimizer preservation proofs. |
| **K Framework** ([manual](https://kframework.org/docs/user_manual/)) | Executable configuration/rewrite semantics and program analysis/verification workflows. | Alternative to developing a new semantics DSL. Use for one small C-like semantic reference if the oracle needs language-level transition semantics. |
| **Plotkin & Pretnar (2009), _Handlers of Algebraic Effects_** ([paper](https://www.research.ed.ac.uk/files/17909848/Plotkin_Pretnar_2009_Handlers_of_Algebraic_Effects.pdf)) | Explicit handlers for effectful computations; algebraic state/effect interpretation. | Better candidate than universal DTOs for explicit environment/behavior separation, but *not* a universal model of compiler facts. |

## What this changes (not a paraphrase of framework marketing)

1. **Novelty constraint:** independent extension composition is substantially addressed by ableC/Silver and MLIR. A UT research contribution needs a reproducible **incremental cross-representation/semantic collaboration** discriminator under explicit selected-world identity and adversarial revocation. Even that may have close prior art; novelty remains unproven.
2. **Smaller architecture control:** MLIR interfaces + ordinary C# typed interfaces often address the original “new behavior without modifying old types” need more directly than a generalized ontology. Compare them before introducing `SemanticFactStore`.
3. **Safety is downstream of truth provenance:** Soufflé can explain `R` from `P` and `Q`, but does not certify `P` and `Q`; an agent-generated proof DAG with false premises is still false. Define source authority first.
4. **Invalidation is about ownership:** LLVM/Salsa show difficult cache semantics with mutating representations. A query scoped to an immutable program snapshot can simplify the first experiment. Avoid optimizing invalidation before profiling its actual cost.
5. **Language semantics must precede optimization claims:** CompCert/Alive2 encourage a deliberately small operational/observational semantics for bounds, traps, overflow and memory. A full “no UB C99” compiler is not a realistic E1 prerequisite.
6. **Representation independence is a capability, not the absence of adapters:** translating across unrelated IRs intrinsically loses or changes information. Typed mappings or target reanalysis are *necessary work*, not merely undesirable glue.

## Stronger experimental competitors

- **Direct C# baseline**: frozen shared `ISafeIndexAnalysis` contract; independent `Shape`, `Range`, `RangeV2` assemblies; explicit versioned cache keys and conservative invalidation. This baseline is permitted to use a shared registration helper and excellent diagnostics.
- **MLIR-style baseline**: operation/interface model with dynamic operation traits and canonical analysis invalidation; same authoring budget, oracle corpus and hard failures. Do **not** require its source IR to be identical to UT's for an unfair comparison: explicitly separate representable scope from genuine cross-family differences.
- **UT treatment**: exact selected `LanguagePlan` and evidence query; no source-level modifications to frozen prior assemblies. Count central schemas, adapters, generator output and migrations in total footprint.

## Literature limits

The comparisons are based on official manuals/paper abstracts and selected detailed documentation, not complete source audits or theorem re-proofs. They establish **specific prior-art capabilities**, not comprehensive side-by-side performance results. The most important missing evidence is a common held-out UT-bound workload with a non-UT oracle and a directly comparable mature alternative.
