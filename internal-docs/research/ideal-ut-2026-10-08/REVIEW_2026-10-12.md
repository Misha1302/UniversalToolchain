# Ideal UT — independent architecture review (2026-10-12)

**Status: independent research assessment, not an accepted ADR, proof, merged feature, or implementation report.** Audited `master@886bf241623e83566585bf2aec5b635fefe1675f` by GitHub repository metadata, targeted current source inspection, and existing repository research; no local checkout, build, CI replay, executable benchmark, or external human holdout was performed during this review. All recommendations remain conditional.

## Executive research result

**The next likely leverage point is verified *semantic interoperability at the consumer decision*, not universalizing the compiler's object model.** UT's existing configuration composition is genuine; arbitrary semantic interoperability is not established. The best immediate candidate is a small, versioned query/obligation protocol evaluated *within the already-selected plan*, but a well-designed typed C# interface baseline remains the preferred solution unless E1/S2 show a real advantage.

Do not interpret “open world” as “every extension composes successfully.” A reasonable target is: independently built extensions either (a) compose under explicit checkable preconditions, or (b) deterministically decline with an actionable reason. This weaker but testable formulation avoids a false universal-compatibility theorem.

The most consequential distinction is between **information shared** and **permission to change program behavior**. A plugin may submit information; only a named, trusted verifier/consumer policy for the exact revision may authorize a correctness-sensitive rewrite. Even a flawless fact database would not solve the authority problem by itself.

## Three viable strategies and the decision frontier

| Strategy | Advantage | Serious limitation | When it wins |
| --- | --- | --- | --- |
| A. Fixed, ordinary C# pipeline + typed interfaces and explicit adapters | Least infrastructure for a known language and IR; discoverable tooling; straightforward lifecycle | New third-party interactions can require adapters/recompilation of shared registration | Closed workloads, few interoperating extensions; equal E1 safety/cost |
| B. Extend current UT with a narrow scoped semantic query/obligation adapter | Reuses unique configuration owner and current verifiers; supports independent providers without making every IR globally uniform | Scope, executable identity, revocation, ambiguity and trust policy are hard; can be higher total cost | E1 demonstrates genuine N+1 without consumer edits or false-safe rewrites and with manageable total glue |
| C. Universal fact/relations engine with cross-IR proof, rewriting and inference | Maximum expressiveness for nontrivial deductive collaborations | Enlarged soundness/authority surface, fixpoint cost, ontology/versioning and cache invalidation; weak immediate demand | Only after at least two *different* UT-bound transitive derivation use cases beat A/B |

**Recommendation: evaluate B, retain A as default, defer C.** Do not freeze a new stable semantic-fact SDK before the adversarial tests.

## Proposed ownership model, without a second planner

```text
package/feature contributions
        ↓
LanguageDefinition ──> LanguageCompiler (only global selection authority)
                              ↓
                     immutable LanguagePlan
                              ↓
                   LanguageRuntime (exact materialization)
                              ↓
           program/IR snapshot with revision identity
                     ┌────────┴───────────┐
             typed analyses          transform candidate
                     │                     │
           scoped evidence ──> consumer obligations / host trust policy
                                           │
                                    independent check
                                       │       │
                                  legal       unknown/conflict/unsafe
                                       │       └─> no rewrite + explanation
                               new artifact/revision
                                       │
                              bounded invalidation
                                       │
                                  selected backend
```

A plan is a *configuration* snapshot, not a proof. Program analysis must not select fresh packages or runtime executors. A provider is only considered if its exact implementation is selected by that plan; a newly installed package requires an explicit configuration/replan, not dynamic discovery while optimizing an old program.

### Minimal semantics sketch (proposal, not a shipped interface)

Let `W = (PlanHash, SelectedExecutableDigests, Backend, TrustPolicy)`, and `S=(ProgramDigest, IRKind, IRRevision, Phase, Anchors)`. A fact key is `(PredicateSchemaId, SchemaVersion, Subject, W, S, Assumptions, PathCondition)`. Evidence is a *claim* plus polarity, source identity, verifier identity, premise fingerprints and validity bounds. A consumer query maps selected admissible evidence to `{Proven, Disproven, Unknown, Contradiction}` (only `Proven` under the explicitly named policy can satisfy an obligation). If a schema version, subject, executable digest, backend, revision, assumption or trust policy differs, evidence is not silently reusable.

```text
Query(P, subject, world, snapshot):
    admissible := verifyScopeAndTrust(selectedProviders(world).claims(P, subject))
    return fourValuedJoin(admissible)  // neither, +, -, both

TryTransform(T, snapshot):
    requirements := T.obligations(snapshot)
    if any(Query(r) != Proven for r in requirements):
        return NotApplicable(Explain(requirements))
    candidate := T.apply(snapshot)
    if not IndependentCheck(T.observationModel, snapshot, candidate):
        return Rejected
    return NewRevision(candidate, invalidateAffectedEvidence())
```

This is a **contractual outline**, not a complete validator. In particular, a checker must not assume that a self-asserted `Pure` or `preserves` is a certificate. No semantic equivalence is assumed across distinct artifacts. Where a transformation cannot be independently checked, an explicitly narrower trusted pass policy is required; do not label that a mathematical proof.

### Bounds-check example with actual failure modes

For `Read(a,i)`, safe check removal requires `0 ≤ i < len(a)` on the exact reachable path, and a length-stability guarantee (aliasing, intervening writes, concurrent mutation), matching signedness/overflow, exception/trap behavior and backend observation model. A new independent `RangeAnalysisV2` should help an unchanged `BoundsOptimization` via a shared narrow query. Merely transferring source spans to AIR cannot transport `SafeIndex`: one-to-many lowering, effects and changed evaluation order require a checked transport witness or reanalysis. Missing provider, an untrusted declaration, contradictory evidence or stale program revisions preserve the check.

### Semantics, representations and typing

Treat `Language` (user-visible syntax/types), `SemanticDescriptor` (meaning/observable effects), `ArtifactContract` (representation and verifiable invariants), `Provider` (implementation), and `ProofObligation` (action legality) as different notions. An IR may contain nested regions or another representation, but no universal AST→Bytecode→AIR→SSA linear pipeline is mandated. A handler interface is about *which operations can be processed*; it does not prove *semantic equivalence* of a rewrite.

A C-like language with no UB is **not** “C99 but cleaner”: it needs a specified behavior for every previously undefined case, choices for integer overflow, pointer provenance, lifetime, races, evaluation order, FP and exceptions/traps; such a language is a distinct dialect with its own observable semantics. Neither System F nor dynamic typing implies speed. Benchmark after semantics and representation are fixed.
