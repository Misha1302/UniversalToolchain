**Status: PROPOSED / NOT_RUN.** Prior isolated Python and .NET spikes reported by [SOURCES.md](SOURCES.md) are historical wiring demonstrations, not an integrated UT outcome. The independent control A (direct typed C# interfaces plus handwritten adapters) is the default simpler competitor, B is MLIR-style operation interfaces and explicit conversions, C is scoped semantic facts/provenance/obligations. ## Universal preregistration and measurement

For each run, freeze before execution: experiment ID/hypothesis, intended falsifier, three competing implementations A/B/C or documented inapplicability, UT commit, program and package SHA, .NET SDK/runtime/OS, chosen `LanguagePlan` + actually selected implementation digests, producer/consumer binaries, deterministic seeds, independent reference oracle and held-out corpus. Capture setup time, LOC by package (including registration/adapters), consumer+producer touched files, diagnostics, positive/negative result, false-safe and false-negative counts, compilation/materialization time, first call, steady throughput, memory/allocations, invalidation cost, trial variance, raw observations and minimal failing input. Declare acceptable overhead and decision margin **before** run; no invented quantitative threshold from absent measurements. Record `NOT_RUN`, `PASS`, `FAIL` or `BLOCKED` per [DoD](DEFINITION_OF_DONE.md).

A **false-safe** means removing or selecting a transformation that independent observation disproves on in-scope inputs. Hard threshold for every correctness gate: exactly **zero**. A positive test without mutation/independent oracle does not establish proof. Tests listed below are designs, not executed commands.

## E1 — N+1 semantic interoperability | G02, G03

**Question / competing hypothesis:** Does C enable precision improvements from independently compiled RangeAnalysis, ShapeAnalysis and unchanged BoundsOptimization better than simple A/B? **Integrated minimum:** actual `Read(a,i)` with a real emitted bounds check; independently built producer packages, no implementation-reference dependency between provider and consumer. RangeV2 separately produced; no edits/rebuild of old consumer/source packages from code changes; loading new binaries allowed. **Controls:** same frozen program/fixtures/compiler semantics for A, B and C, including manual shared helper for A (strong control); hash old binaries and report registration overhead. **Corpus:** safe edges (zero/index=last), too-small/negative indexes, signed/unchecked/checked overflow, aliased array write, path-specific conditions, partial range, contradictory facts, incomplete dependencies, unresolved provider, stale revision/backend/phase. **Expected observable:** exact emitted check kept for unknown/unsafe; removed only on independently validated safe path; RangeV2 gains at least one additional *legal* held-out case without modifying previous packages. **Stop:** any false-safe; no precision delta; N+1 needs old consumer changes; A/B equal outcome at materially lower lifecycle cost. **Evidence:** `evidence/E1/{manifest,controls,raw,oracles,mutants,costs,critique}` to be created at execution. **Next:** choose A/B and close C, or conditionally G03; do not integrate before G09.

## E7 — adversarial trust and exact identity | G03

**Question:** Can an untrusted provider or stale artifact escalate a proposal into a correct-looking `Proven`? **Slice:** same E1 UT check-elision candidate with independent authority checks and exact execution context; run every corruption separately. **Independent controls:** original unoptimized program + authoritative reference evaluator, not provider-supplied proof. **Negative/mutation corpus:** forged `Pure`, malicious effect claim, wrong binary SHA, recompiled provider with same package label, contradictory Range/Shape, swapped backend, mutated `ProgramSnapshot`/AST/IR, stale editor document version, path mismatch, incomplete provenance/dependencies, concurrent invalidation, altered trust policy. **PASS:** every invalid/untrusted item fails closed and *cannot* remove a check, with deterministic reason; 0 false-safe. **FAIL:** one case authorizes unsound transform. **Cost:** log hashing/recheck overhead and cache hit/miss. **Stop:** revert optional fact adapter and keep explicit verified manual pipeline. **No claim:** `LanguagePlan` validation is not a sandbox. **Evidence:** `evidence/E7/`.

## E2 — honest cross-representation correspondence | G04

**Competing hypothesis:** explicit scoped witness adds value over recalculating on destination IR. **Slice:** actual AST expression mapping to multiple AIR instructions and optionally verifier-gated SSA, with overlapping paths and a real check or side effect. **Controls:** independent evaluation before/after, source-map-only negative, recompute-local-facts baseline. **Corpus:** one-to-many, changed arithmetic overflow mode, trap/throw, FP signed zero/NaN, heap write/alias, reordered effects, insufficient mapping, stale IDs, dead/missing value. **PASS:** equivalence only within declared observations under checked witness; bad mappings reject transfer. **FAIL:** source location alone treated as proof, observed semantic mismatch authorized. **Stop:** abandon transfer, recompute facts. **Evidence:** `evidence/E2/`.

## E3 — legality before cost | G05

**Competing hypothesis:** program-scoped obligations can choose legal transforms without duplicating global composition. **Slice:** two actual programs compiled with identical frozen `LanguagePlan` and selected executable set, but distinct truth of `SafeIndex`/effects obligations. **Controls:** fixed legal-plan static route and a deliberately illegal cheaper candidate; reference execution. **Negative:** stale evidence, mutable plan, backend changes, mandatory pass omitted, cheapest invalid transformation. **PASS:** different program-local legal behavior, same global selected providers/routes/plan; no unsafe transform or mandatory pass bypass. **FAIL:** any re-planning of packages, providers, routes or illegal cost-first choice. **Stop:** revert local feasibility and retain static route. **Evidence:** `evidence/E3/`.

## E4 — independent external language authoring | G06

**Competing hypothesis:** UT SDK lowers authoring cost compared with ordinary manual C# pipeline. **Slice:** external package for non-Wist typed Rules/Policy DSL: grammar, name binding, user types, precise spans, invalid source diagnostics and execution; a second semantically different family (configuration/tensor) held out before promotion. **Controls:** same DSL manual pipeline + current low-level SDK + proposed helper. **Negative:** unknown symbol, type mismatch, malformed input, missing backend capability, package ambiguity, no Wist dependency allowed. **Metrics:** clean setup time, author-changed LOC and files, manual registrations, correctness, executable package creation; independent third-party author. **PASS:** clean SDK consumer can build/run/diagnose and has measurable authoring benefit without duplicate planner; if no benefit keep SDK unchanged. **Evidence:** `evidence/E4/`.

## E5 — language services and actual editor use | G07

**Competing hypothesis:** shared batch compiler services enable safe editor tooling without another binder. **Slice:** valid→invalid→valid on same E4 independent DSL; versioned document snapshots + diagnostics, hover/completion/definition and read-only LSP projection. **Controls:** batch compiler outputs at each version and naive full reparsing; forced response reordering/cancellation. **Negative:** stale version, non-existent symbol, shifted span, partial/error AST, unauthorized agent edit. **PASS:** 100% stale-result rejection in specified adversarial trace and no diverging symbol/type semantics; user completes workflow with independent diagnostics. **Cost:** incremental vs full reanalysis time/memory, errors and manual steps. **Evidence:** `evidence/E5/`.

## E6 — bounded cost / amortization | G08

**Competing hypothesis:** specialization pays for planning and materialization at target invocation counts, compared with static handwritten and current interpreter/CIL. **Slice:** exact same semantics and backend configuration with measured planning, compilation, materialization, first call, steady throughput and rebuild/invalidations. **Controls:** handwritten pipeline, existing UT path, specialized UT path; matching warmups, compiler flags, input distributions and numerics. **Negative:** rare compile-heavy churn, frequent source revisions, path guard misses, proof cache invalidation, memory pressure, fallback. **Metric:** break-even calls using total cost, confidence/variance and regressions reported, not best-case latency. **PASS:** complete raw measurements and preregistered workload threshold met; otherwise negative finding/DEFER. **Evidence:** `evidence/E6/`.

## E8 — source and run reproducibility | G00, G01, G08, G10

**Competing hypothesis:** an independent runner can regenerate exact outputs without developer-machine state. **Slice:** selected project at exact SHA and package hashes, SDK/environment, commands, seeds and reference outputs, raw logs, independent holdout. **Controls:** clean checkout with no cached builds, separate environment when available. **Negative:** changed commit, stale package, changed backend, missing dependency or seed, unrepeatable results. **PASS:** repeated generated digests and observations match the preregistered tolerance; failures reported without status inflation. **FAIL:** claim of reproducibility without replay or mismatched SHA. **Evidence:** `evidence/E8/`.
