# Definition of Done — authoritative acceptance owner

**Applies to proposed work; not proof of completed experiments.** Status starts `NOT_RUN` for every gate. `PASS` requires artifact-bound evidence; do not promote with document assertions. Allowed: `NOT_RUN`, `IN_PROGRESS`, `PASS`, `FAIL`, `BLOCKED`.

## DoD by artifact type

- **DOC-RESEARCH / hypothesis:** falsifiable question and preregistered competing A/B/C; pinned code/literature baseline; raw positive, negative and mutation data; independent oracle and adverse counterexample protocol; peer critique with unresolved findings; reproducible commands and scoped conclusion including abandonment option. A source summary is not an experiment.
- **DOC-POC / prototype:** runnable exact SHA/SDK/OS with named dependencies, separate builds where independence claimed, selected UT-integrated path or prominent `ISOLATED ONLY`; unit/integration/negative/mutation tests; raw measurements with warmup; fallback path; no new public API by default. If only a toy runs, report only wiring evidence.
- **DOC-CORE / IR transform:** exact observation scope (values, checked overflow, signedness/FP, traps, exceptions, alias/heap, ordering/effects), preconditions/obligations and selected executable digests, negative tests and independent oracle, invariant that Unknown/Contradiction/Disproven cannot license a destructive transform, old execution path preserved on refusal, selected plan unchanged, API/backward behavior verified.
- **DOC-PUBLICAPI / SDK:** package-compiled clean-room consumer, semantic second independent language, no Wist namespace dependency, source snippets actually restore/build/run, compatibility matrix, version/migration/rollback, external usability scenario and maintainer review. E4 authoring checks grammar, binder, types, invalid inputs and exact backend output.
- **DOC-TOOLING:** versioned immutable `DocumentSnapshot`, authoritative batch parser/binder, stale-request/cancellation/race tests, precise diagnostics, thin LSP/CLI/MCP projection, read-only agent default and explicit authorization to modify; no duplicate resolver or security claim from planner.
- **DOC-PRODUCT:** independent author completes edit→validate→run flow on clean install; compare manual pipeline, measured author time and code changes; no fake safety guarantee.
- **DOC-E8 / reproducibility:** exact source/package SHA, source of oracle, compiler/OS/SDK/config/seeds, raw logs, fixed negative cases, independent holdout and minimized counterexample, retained under evidence/ path outside production code; `UNKNOWN` where replay unavailable.
- **DOC-RELEASE:** exact candidate/reviewed commit; CI/test outcome on that SHA, package identity and reproducible pack, old external consumer and Windows/Linux compatibility (or explicit unsupported platform), security/limit labels, migration and rehearsed rollback; public release needs separate approval and canonical packaging prerequisites.

## Evidence-to-status rule

Record gate observations and status only in the approved decision/handoff receipt on execution; this matrix's initial `NOT_RUN` must not silently change. `FAIL` means the stated alternative falsifier occurred, not that the whole project failed. Performance comparison requires preregistered target range and acceptable regression envelope; until then G08 cannot become `PASS` merely because a benchmark was executed.
